# 2026-11-13

Environment scatter, item 3 of the procedural-world list: `terrain/include/aether/terrain/scatter.h`. Rules (biomes, height, slope, distance
from water, a patchiness noise, density, clumping, scale, tilt, footprint and overlap) run in order over a generated terrain; each rule
draws from its own random stream and a later rule keeps clear of the footprints of the earlier ones, so the order is the pecking order
(trees, then shrubs, then grass) and adding a rule at the end moves nothing before it (a test holds that). `DefaultScatterRules` is a
temperate starter set. `ToFoliageInstances` feeds the existing foliage layer (rule index becomes `type_index`).

On the 513 x 513 terrain the default rules place about 44,000 instances in 38 ms (single thread, one run; 37,000 of them grass). Looking at
the preview found two things that were not bugs in the placer: the overlay drew grass over the trees (earlier rules draw on top now), and
a forest wanted a higher pine density than my first guess (1.6 to 4 per 100 square metres).

Not done: the procedural mesh generator and the visual editor (items 2 and 4); wind and seasonal variation; GPU instancing for the result
(the RHI has no instanced draw, see PERFORMANCE.md); an MCP tool; a saved `.ascatter` rule asset; slope-aware spacing; exclusion zones
(paths, buildings) beyond other rules' footprints.

Editor, Stage 0 of [the parity audit](../design/EDITOR_PARITY_AUDIT.md), the data-safety slice: the open scene can no longer be lost to a quit or a crash. A quitting editor asks before the title-bar X and File > Quit do anything (`Window::on_close` can now refuse the close), autosave writes the dirty scene into a per-project recovery slot, and the next launch offers that slot back. The design decision worth recording is that there is one slot per project, not a directory of timestamped copies: the slot is removed on save, on undo back to the saved state and on a normal quit, so its existence *is* the evidence that the last session ended badly. Recovery brings the scene back dirty under its own name with the file on disk untouched, and it is the same atomic writer the crash test already covers. `EditorSettings` v1 (autosave on/off and interval, behind View > Preferences) lives in `%APPDATA%/Aether`, versioned so an older editor ignores a newer file rather than guessing. All of it is headless-testable: the quit answers are public, and the autosave root moves with `AETHER_EDITOR_AUTOSAVE_DIR`.

Not done in this stage yet: the command registry (with duplicate-id and chord-conflict tests), the `EditorDocument` contract above the scene, notifications and the Messages panel, and native open/save dialogs. Autosave and the quit prompt cover the scene document only; the other asset editors still keep their own documents and do not ask.
