# 2026-11-14

Procedural mesh generator, item 2 of the procedural-world list: `engine/include/aether/assets/procedural_mesh.h` (engine layer, so every
module can use it). It makes the engine's own `MeshData` (one primitive per material), so a piece cooks, draws and saves like an imported model.

- `MeshBuilder`: triangles, boxes, tubes with parallel-transport frames, icospheres; smooth normals welded by position (a UV seam does not crease)
  or flat; tangents from the UVs.
- Generators: `GenerateRock` (icosphere pushed by 3D fractal noise, planar cuts for split stone, flattened bottom, sits on y = 0),
  `GenerateCliff` (a displaced face with strata ledges, closed to a back plane at z = 0 so it stands against a slope), `GenerateTree`
  (pine tiers; broadleaf and dead trees by recursive branching, leaf masses at the twig tips; scaled so the tip is exactly `height`),
  `GenerateBuilding` (bays and floors, windows with panes and trim, a door, gable or flat roof, chimney), `GenerateModular`
  (wall, pillar, arch, stairs).
- `GenerateVariant(kind, index, seed)` draws every parameter from the kind's own ranges: 300 variants of rocks, pines or broadleaf trees are 300
  different meshes (a test hashes them). `ValidateMesh`, `ComputeStats` (signed volume, open edges) and `EncodeGlb` (read back by the engine's own
  glTF loader in a test).

Looking at the rendered gallery (all kinds, in the player) found two things the tests had not: broadleaf trees came out 1.6 times their requested
height and averaged 22,000 triangles (up to 67,000). They are fitted to the requested height now and average 5,300 (at most 9,500); a per-kind
triangle budget is part of the test. 600 pieces generate in about 0.8 s.

Not done: LODs; real UV layouts (rocks and cliffs are box-projected, trees' leaves too); the cliff's strata are too regular and read as stacked
shelves (by eye); roofs other than gable and flat; interiors; the building's gable end meets the roof with a sliver at one edge; an MCP tool; a
visual editor (item 4).

Editor, Stage 0 of [the parity audit](../design/EDITOR_PARITY_AUDIT.md), the command registry: File, Edit and View menus, the command palette and both
keyboard scopes now read one table (`editor/src/workspace/command_registry.{h,cpp}`) instead of three hardcoded lists. A command is an id, a label, a
menu and separator, a chord, a scope and optional enabled/label functions; `Add` refuses a duplicate id, and a startup test asks for chords that could
fire together and requires none, where a `Global` chord overlaps everything and the others overlap only their own scope. The scope is the part worth
recording: the workspace polls `Global`, the Scene toolbar polls `Scene` and the hierarchy `SceneTree`, and exact-modifier matching means Ctrl+S in a
focused graph editor does not also save the scene. File > Quit and Ctrl+Shift+P became ordinary entries, so the shell no longer has a Quit item of its
own. Two things the tests caught: `editor::CommandContext` already names the command-stack context, so the registry's enum is `CommandScope`, and the
palette's empty-query count had to become tools + commands, since commands are now listed after tools and before assets.

Not done in this stage yet: the `EditorDocument` contract above the scene, notifications and the Messages panel, and native open/save dialogs.

Editor, Stage 0 of [the parity audit](../design/EDITOR_PARITY_AUDIT.md), the document contract: `EditorDocument`
(`editor/src/core/editor_document.{h,cpp}`) is the small set of questions the shell may ask any open document -- file path, display
name, kind, dirty state, undo/redo with labels, and save (with a path: save-as). `SceneDocument` implements it without a wrapper, and
`EditorWorkspace::ActiveDocument()` hands it to the quit prompt, which now says "The open scene has changes..." from `Kind()` and
names the document from `DisplayName()` instead of reading the Scene panel's fields. The line drawn is that a document owns its edit
state while a panel owns its window and naming defaults: ScenePanel::SaveScene keeps the overwrite check and the status line in front
of `SceneDocument::Save`, and Stage 6's asset documents will front the same `Save`. Two tests: a scene answered through the base class
(clean after undoing back to the saved state, save-as renaming it, a plain save writing to the existing path) and a non-scene stand-in
proving the default display name works for any document.

Still open in this stage: notifications and the Messages panel, and native open/save dialogs.
