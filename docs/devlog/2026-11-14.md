Procedural mesh generator, item 2 of the procedural-world list: `engine/include/aether/assets/procedural_mesh.h` (engine layer, so every
module can use it). It makes the engine's own `MeshData` (one primitive per material), so a piece cooks, draws and saves like an imported model.

- `MeshBuilder`: triangles, boxes, tubes with parallel-transport frames, icospheres; smooth normals welded by position (a UV seam does not crease)
  or flat; tangents from the UVs.
- Generators: `GenerateRock` (icosphere pushed by 3D fractal noise, planar cuts for split stone, flattened bottom, sits on y = 0),
  `GenerateCliff` (a displaced face with strata ledges, closed to a back plane at z = 0 so it stands against a slope), `GenerateTree`
  (pine tiers; broadleaf and dead trees by recursive branching, leaf masses at the twig tips; scaled so the tip is exactly `height`),
  `GenerateBuilding` (bays and floors, windows with panes and trim, a door, gable or flat roof, chimney), `GenerateModular`
  (wall, pillar, arch, stairs).
- `GenerateVariant(kind, index, seed)` draws every parameter from the kind's own ranges: 300 variants of rocks, pines or broadleaf trees are 300
  different meshes (a test hashes them). `ValidateMesh`, `ComputeStats` (signed volume, open edges) and `EncodeGlb` (read back by the engine's own
  glTF loader in a test).

Looking at the rendered gallery (all kinds, in the player) found two things the tests had not: broadleaf trees came out 1.6 times their requested
height and averaged 22,000 triangles (up to 67,000). They are fitted to the requested height now and average 5,300 (at most 9,500); a per-kind
triangle budget is part of the test. 600 pieces generate in about 0.8 s.

Not done: LODs; real UV layouts (rocks and cliffs are box-projected, trees' leaves too); the cliff's strata are too regular and read as stacked
shelves (by eye); roofs other than gable and flat; interiors; the building's gable end meets the roof with a sliver at one edge; an MCP tool; a
visual editor (item 4).

palette's empty-query count had to become tools + commands, since commands are now listed after tools and before assets.

Editor, Stage 0 of [the parity audit](../design/EDITOR_PARITY_AUDIT.md), the document contract: `EditorDocument`

(clean after undoing back to the saved state, save-as renaming it, a plain save writing to the existing path) and a non-scene stand-in
proving the default display name works for any document.

Editor, Stage 0 of [the parity audit](../design/EDITOR_PARITY_AUDIT.md), notifications: the error-only toast widget that no

Editor, Stage 0 of [the parity audit](../design/EDITOR_PARITY_AUDIT.md), native file dialogs: `FileDialog`
(`editor/src/core/file_dialog.{h,cpp}`) is the one interface every path field can use — title, start path, suggested save name,
filters, save-or-open in, the absolute path or nothing out. The design decision that made it testable was `Available()`: without
it, "the platform has no picker" and "the user cancelled" are both an empty path, and Linux without zenity would have had File >
Save As silently do nothing (or worse, fall back to the typed path after a cancel). Windows uses the shell's common item dialog;
Linux runs zenity, then kdialog, with argv rather than a shell string so a path cannot become a command. `File > Open Scene`,
`File > Save Scene As` and the Scene toolbar's "..." go through it; a scene picked under the content folder is named there
relative to it, one from elsewhere keeps its absolute path. Because the save picker already asked about replacing an existing
file, the panel gets `overwrite=true` instead of asking a second time.

returning false quietly, and the open project and list stay as they were. Creating from a template reuses the panel's

Editor, Stage 1 of [the parity audit](../design/EDITOR_PARITY_AUDIT.md), the main toolbar: one strip under the menu bar
(`EditorWorkspace::DrawMainToolbar`, in the shell's top side bar). The governing choice was that the toolbar owns no
state and no logic of its own. Save/Undo/Redo run command ids, so their enabled predicates and chord strings are the
registry's and the tooltips cannot drift from the menu or palette; the move/rotate/scale, world/local and snap controls
are the Scene View's `ViewportTools::DrawToolbar` rather than a second copy, so a W press in the view and a Move click

`PlaySession::Step()` is now reachable twice over: `SceneDocument::Step()` and `SceneDocument::ShouldSimulate()`, which
a host asks each frame. The Step button is enabled only while paused, where it advances exactly one frame; while playing
it is disabled rather than silently ignored. The play state also draws a thin amber underline across the toolbar, the
first piece of the PIE affordances the later stages build on.

Build and Package and Settings are new palette commands (`project.build`, `project.settings`) that open their tool in
its own window, so the toolbar action is a command like every other, even though neither has a menu yet. Tests: Step's
one-frame semantics through the document (also the stage gate), the toolbar's undo/redo enablement following the
document, both tool actions opening their windows, and the toolbar drawn headlessly in editing, playing and paused
states.

Editor, Stage 1 of [the parity audit](../design/EDITOR_PARITY_AUDIT.md), the status bar's last two segments: how many
entities are selected, and which source-control branch the project is on. `QueryGitBranch` (`engine/src/assets/vcs.cpp`)
asks git with `symbolic-ref --short HEAD` -- which answers on an unborn branch, where `rev-parse HEAD` does not -- and
falls back to the abbreviated commit id on a detached HEAD; outside a repository it returns empty and an explanation
rather than pretending. The workspace caches it, reading it when a project opens and when the shell calls
`RefreshSourceControl()` every 300 frames, so a checkout made outside the editor appears within seconds instead of git
being spawned every frame. A host can set it directly (`SetSourceControlBranch`), which is also how the test shows a
branch without depending on the checkout it runs in. `StatusBarInfo` carries `branch` and `selected`; the bar leaves
the selection out at zero and the branch out when there is none. Tests: the selection count following the document's
selection, the branch drawn and cleared and surviving a refresh, and a real repository read through init, an unborn
branch and a renamed branch, with a quote in the path refused.
