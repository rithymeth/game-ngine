# 2026-11-15

The visual generation editor, item 4 of the procedural-world list, as editor panels (`editor/src/world/procedural_document.h`, `procedural_panel.h`).

- `ProceduralWorldDocument` (headless, like the other documents): every setting of the terrain generator, the scatter rules, and a mesh family per rule;
  four presets (temperate, alpine, desert, islands); undo that takes one step per edit and not per slider tick; seeds and a dice button; Generate; a
  preview picture; and three ways out. `ApplyToTerrain` hands the heightmap, layers and splatmap to the Terrain editor (its sculpt tools carry on),
  `ApplyToFoliage` the instances to the Foliage editor (one undo step), and `Bake` writes files under `Content/Generated/<name>/`: the terrain as a model with
  six surfaces, a `.glb` per mesh variant, and an `.ascene` with the terrain and the scatter as model entities, which the player loads.
- `ProceduralWorldPanel`: tabs for Terrain (sliders with tooltips), Scatter (rule list, per-rule editor, mesh family) and Output; regenerates as you edit when
  the last generation was quick, once the edit settles. Registered in the workspace under World.
- The terrain module is not in the player (no terrain component or asset type; the MCP terrain tools say so too), so a bake exports the terrain as a mesh. That is
  why the output is a model and not a terrain asset.

Rendering a baked world in the player found three defects in the generator that the tests had not. Hydraulic erosion made the terrain spiky: it raised the mean
|laplacian| from 0.06 m to 0.47 m, and the cause was the sediment capacity (4, the usual figure for a 0..1 height range, carries metres per droplet on a 60 m terrain);
0.5 leaves it at about 0.11 m and still cuts gullies, and the erosion now digs over a disc and not one cell. Lakes drew on their bumpy beds (a flat surface at each
lake's fill level now, and at the sea level for the sea). A 3x3 smoothing stage (`smoothing`, default 2) was added first as the suspected fix; it barely changed the
roughness (the noise was not the cause) but it is kept as a setting.

Not done: grass, shrubs, reeds and cacti have no mesh generator, so their rules are scattered and shown in the preview but baked as nothing; the terrain's biome
borders are stair-stepped (one surface per quad); the terrain edge is an open lip; a baked scene is one draw call per object (the RHI has no instancing), capped at
5,000 objects by default; no node graph; the terrain's textures are single colours.

## Content browser: multi-select and the batch operations (parity stage 3)

The Content Browser's listing now keeps a selection and acts on all of it at once (`editor/src/content/content_browser_panel.{h,cpp}`).
Click selects, Ctrl toggles, Shift takes the range from the anchor in the current listing, and a rectangle dragged over the grid's
tiles takes every tile it touches (Ctrl+drag adds); Delete, Ctrl+D, Ctrl+A, F2 and Escape work while the listing has focus, and the
selected tiles get an amber border. Duplicate, Delete and Move run over the whole selection as one batch: the new
`assets::DuplicateContent` and `assets::DeleteContents` (`engine/src/assets/content_browser.cpp`) and `MoveContent` per path, then a
single rescan and a single refresh. The engine header's `DeleteContents` reports how many entries it removed, and that number is 0
on refusal -- a delete is all-or-nothing, refused while anything outside the batch refers to something it would remove, with the
users named in the error. Duplicates are named "<stem> copy", "<stem> copy 2", ... with fresh GUIDs and no sub-assets or source
hash, so the copy imports on first use; the copies become the selection, so duplicating again continues from them. Rename happens
in place on the tile or row (`BeginRename`/`RenameEntry`): a name with no extension keeps the asset's, a changed extension is refused
because it would change the type, and renaming the folder being shown keeps it open. The toolbar gained a Create menu that makes one
asset of any registered type (`ExtensionRegistry::CreateAsset`) and starts its rename, plus Duplicate, Delete and the selection
count; the listing's background menu offers Select All, Create, Duplicate and Delete. The transaction is the batch rather than an
undo step: the asset database has no undo, and a file move cannot be represented in the ECS command stack.

Tests: `tests/test_content_multi_select.cpp` -- duplicate finds free names and fresh identities (folders too) and refuses pieces,
meta files and paths outside Content; a delete batch is refused whole while a model outside it uses one of the textures and removes
nothing, then takes the folders once the references are inside it; selection extends, toggles, selects all, clears, and a rectangle
selects the tiles it touches (and only those); duplicating selects the copies and numbers them; deleting through the panel refuses
the batch or takes all of it and already lists the result; moving the selection and the open folder follows it; rename keeps the type
and the selection. The remaining Stage 3 items are the filter chips/folder scope/breadcrumbs/sortable columns/`type:`/`path:` search,
the import settings drawer with reimport and Explorer drag-import, an opener for every asset type, the reference viewer upgrades, and
Reveal in Explorer / copy path.

## Content browser: the search grammar, the type chips, the folder scope and the columns (parity stage 3)

The Content Browser's listing can now be narrowed (`editor/src/content/content_browser_panel.{h,cpp}`,
`engine/src/assets/content_browser.cpp`). The search field takes a small grammar instead of one substring: whitespace
separates words, every word has to match, a `type:` word matches the importer's name and a `path:` word the content path,
all as lowercased substrings -- "crate type:Model", "type:tex" and "path:props/ type:Texture" -- while plain words still
match the name, so every old query means what it did. A word whose value is empty ("type:") is not a term; with no terms
left the search is not a search and does not widen the scope to the subtree. The parse lives in `ListContent`, so the
grammar is the engine's, not the panel's, and a host asking the same query gets the same answer.

The panel's side is UI state and filtering. A chip row under the toolbar lists every importer present in scope with how
many entries it has before the chips apply; clicking one keeps only that type, clicking again drops it, "All" clears the
list. A selected chip stays listed at 0 when a search leaves nothing of its type, because otherwise the chip that caused
the empty listing would be the one thing not on screen to switch off. "Subfolders" sets the scope to the whole subtree,
and the "3 of 12 items" count uses what the scope and the search leave as the denominator, so it describes the chips and
Changed only rather than the scope. The "Content/Models/Crate" line under the toolbar is now a breadcrumb: the current
segment is text, every other one navigates, and "(with subfolders)" says when the listing includes them. The list view's
Name and Type headers sort, with `^`/`v` on the sorted one, a second click flipping the order, and folders first under
either column (still by name when descending). Ctrl+F focuses the search field. An empty narrowed listing says "No
entries match." and offers Clear filters instead of claiming the folder is empty; folders are never hidden by the type
chips, only by Changed only, which is what the VCS test expects.

Tests: `tests/test_content_filters.cpp`. The grammar: `type:model` returns the four glTF models, case-insensitive
`TYPE:TEX` the four textures, `path:textures/` the same four, `path:models/ type:model` the models, and "checker
type:texture" / "cube type:model" narrow to the two checkers and the one cube; "test cube" and "model cube" show that
every word has to match; "type:" and "path:" show that an empty directive is not a term and the folder's own listing
comes back. The panel: chips count the scope (4 models in `models/`, 4 + 4 with subfolders), a chip and a search narrow
together and the chip recounts what the search left, a chip whose type is gone is still listed at 0, Clear filters
restores the listing, the "of" count stays at the scope's total, and a nondescript headless frame draws the chip row,
the no-match line, the breadcrumbs and the sortable headers without tripping an ImGui id clash. Sorting: by Type puts
Model before Texture and flips with descending, folders stay first under both columns, and descending by Name inside
`textures/` starts at `test_solid_red.png`.

Remaining in Stage 3: the import settings drawer with reimport and drag-import from Explorer, an opener for every asset
type, the reference viewer upgrades (find usages, the broken-asset list), and Reveal in Explorer / copy path.
