# Aether Engine v0.27.2 — existing workflow reliability

This pre-1.0 proof release continues the improvement pass over existing
engine features and includes the AETHER-01: First Contact greybox game.

## Improvements since v0.27.1

- Strict cooks include importer and texture-setting warnings with source paths.
- Texture cooking reuses derived data for unchanged sources/settings; a changed
  texture invalidates its own cache entry. Repeat shipping cooks compare both
  archive and cook-manifest bytes.
- Packages stage and verify all artifacts, install the manifest last, and
  restore the previous package after a recoverable installation failure.
- Destination checks prevent a player, DLL or manifest from replacing an
  unexpected directory. `Paks` must be a directory; linked destinations are
  refused. Same-named user files/folders are preserved on validation failure.
- Cancellation after cooking and before installation preserves the previous
  package. A Windows locked-player regression exercises rollback after the
  content folder has already been replaced.
- Package verification requires regular files and rejects linked manifests,
  linked parent folders, NUL/drive/stream paths and repeated paths, including
  ASCII case variants on Windows.
- Cooked archive names must be single filename stems, preventing output from
  escaping the selected output/staging folder.
- Both Windows ZIPs select their release notes from the engine version instead
  of copying notes for a fixed older release.
- Existing sequence teardown/skip stops active media through host callbacks;
  kit composition and scene binding code live in a separate runtime source.
  Content-browser validation and batch operations improve the existing editor.

No new engine feature family or serialized package format is introduced by
this reliability increment. `PackageManifest` remains version 1 with CRC-32.

## Downloads and checks

Extract `AETHER-01-windows-x64.zip` and run `AETHER-01.exe`. Its README lists
controls. `AetherEditor-windows-x64.zip` contains the editor, cooker, pak tool,
player, manuals and built-in plugin catalog.

The release requires the existing Windows MSVC, Linux GCC/Clang/physics/
ASan/UBSan and macOS Apple Silicon CI lanes. Windows gates extract both ZIPs,
verify their checksums, reproduce the game archive using the extracted cooker
without source assets/plugin descriptors, and complete headless and rendered
playthroughs through the archive ending. `RELEASE_MANIFEST.json` records the
build commit and SHA-256 hashes; `SHA256SUMS.txt` covers both primary ZIPs.

## Supported builds and limitations

Downloadable binaries are unsigned Windows x64 Release builds with D3D12,
an AVX2-capable CPU and the Microsoft Visual C++ v14 x64 runtime required.
See bundled `WINDOWS_REQUIREMENTS.md`. Linux/macOS CI verifies source builds;
this release provides no binary package for those platforms.

AETHER-01 is a short greybox proof with temporary art and synthesized sound,
not the polished 15–30 minute slice, 60–90 minute MVP or full five-act game.
The player does not render lighting or skeletal animation; no target-hardware
1080p/60 FPS claim is made. The broader M8 and Aether 1.0 production gates
remain open.

CRC-32 detects accidental damage, not authenticity. Verification covers listed
files and does not lock out concurrent modification. Concurrent updates to one
package folder are unsupported. If rollback itself fails, the error identifies
the retained backup folder. Process crashes/power loss during publication are
not covered by the recoverable-error rollback contract. Full incremental
dependent-asset cooking, signed releases and clean-machine upgrade/rollback
studies remain outstanding.
