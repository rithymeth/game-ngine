# Making a 2D game

The 2D toolkit lives in the `sprite2d` module. Start from the **2D Platformer**
template and read it.

## Sprites

A **sprite atlas** (`.aatlas`) is one texture with named frames (a pixel
rectangle and a pivot) and named animation clips. Cut a sprite sheet into a
grid, or pack separate images into one texture. A `Sprite` component draws a
frame of an atlas at its entity (x and y position, z depth, rotation about z);
a `SpriteAnimator` plays one of the atlas's clips by name. Clip names must be
unique within an atlas; clips can share frames. Frame rectangles must use
whole pixels and fit within the declared atlas size. If the player cannot
load an atlas used by a running animator, its log names the asset and the
reason, including the offending frame for an invalid rectangle. When an atlas
loads but a named animation is missing or empty, the player reports the atlas
and clip once per scene. An unassigned clip remains quiet.
Sprites draw back to front by sorting layer, then order, then z.
Drag an atlas from the **Content Browser** into a scene view or the hierarchy
to place a static Sprite. It starts on the first frame whose name fits the
Sprite field, uses the XY plane in the viewport, and takes one Undo to remove.
Add a SpriteAnimator separately when you want it to play a clip.

Double-click an `.aatlas` in the **Content Browser** to open **Sprite Atlas**
under **Tools > 2D**. The inspector shows frame rectangles and
pivots. Choose a named clip and press **Play** to preview it, or select
**Manual frame** to step through individual frames. The **Source sheet**
outlines the selected frame. Click a frame on the sheet to switch to it
and stop the clip preview; margins and gutters leave the selection alone.
With one static Sprite selected in the scene that uses this atlas, choose
**Use frame on selected Sprite** to apply the manual frame. This changes the
scene in one Undo step, not the atlas file. To assign an animation instead,
add a **Sprite Animator** to that Sprite, select a named clip, and choose
**Use clip on selected Sprite Animator**. This changes only its clip name;
its speed, start time, and Playing setting are kept. Both actions are
unavailable during Play or Simulate. Metadata stays visible even when the
source texture is missing or no longer matches the atlas. To jump from a
selected scene Sprite to its assigned atlas, use **Asset > Open selected
Sprite's atlas** (also in the Command Palette). It opens on the assigned
clip, or on the assigned still frame when there is no matching clip.
If an atlas frame is renamed or removed, strict cooking rejects a scene's
static Sprite that still names the old frame when its atlas is in the same
archive. It also rejects an assigned clip no longer in that Sprite's atlas.
Select the updated frame or clip before packaging again.

To slice a sheet in the editor, right-click a project texture in the
**Content Browser** and choose **Create Sprite Atlas…**. Enter the cell
width and height. For padded sheets, set **Outer margin X, Y** for the equal
borders on opposite edges and **Gutter X, Y** for the gaps between cells.
The editor opens the new atlas in the inspector and never replaces an existing
one. Expand **Named animation clips** to add clips by name, zero-based first
frame, frame count, and FPS. Turn off **Loop** for a clip that holds its last
frame. Leave the list empty for the default whole-sheet loop.
For batch authoring, use `aether_sprite_grid` from the SDK or engine build:

```sh
aether_sprite_grid MyGame/MyGame.aproject "Sprites/Hero.png" 16 16
```

The example generates `Content/Sprites/Hero.aatlas` next to the sheet. Without padding options, the
cells must divide the image exactly. Frames are
named `frame_0`, `frame_1`, and so on, left to right and top to bottom.
Choose the `grid` clip on a SpriteAnimator to play all frames in that order
at 12 fps, or use one frame directly on a Sprite. The atlas references the
imported sheet, so cooking the atlas also includes its texture. The command
won't replace an existing atlas or its metadata.

For a padded sheet, `--margin X Y` describes an equal border on opposite
edges, and `--spacing X Y` describes the horizontal and vertical gaps
between cells. The sheet must still contain only whole cells. For example,
a 54 by 36 sheet fits a 3 by 2 grid of 16-pixel cells with a one-pixel
border and two-pixel gutters (`--margin 1 1 --spacing 2 2`).

For a sheet containing several animations, repeat `--clip NAME FIRST COUNT FPS`
to replace the default clip with named loops:

```sh
aether_sprite_grid MyGame/MyGame.aproject "Sprites/Hero.png" 16 16 --clip idle 0 4 6 --clip run 4 6 14
```

This makes `idle` use frames 0–3 at 6 fps and `run` use frames 4–9 at 14 fps.
The source sheet must have at least ten cells for this example. The indices
are zero-based, each count is positive, and rates are whole numbers from 1
to 240. Clips can share frames but must use unique names (letters, digits,
underscores and hyphens; at most 31 characters so SpriteAnimator can store
the name). All sheet frames stay available to Sprites.

Use `--clip-once NAME FIRST COUNT FPS` in the same command for a clip that
plays once and holds its last frame. For example, `--clip-once land 10 3 12`
adds a landing animation using cells 10–12. Names must be unique across
looping and one-shot clips.

## Tilemaps

A **tileset** (`.atileset`) cuts a texture into tiles, marks which are solid,
and holds **autotiles**: sixteen tile choices indexed by which of a cell's four
neighbours match, so painting a block of ground picks the edges and corners for
you. A **tilemap** (`.atilemap`) is layers of cells over a tileset; a
`TilemapRenderer` draws it. In the editor, **Tools > 2D > Tilemap** paints,
fills and erases, edits layers, sets solid tiles and rules, and undoes strokes.
The palette and canvas show the authored tileset image, including sheet
margins and spacing. If the image is unavailable or does not match the
tileset dimensions, both fall back to swatches so editing can continue.
If a packaged texture has different dimensions, the cooker names both assets
and sizes in a warning. This also checks source images if texture cooking is
disabled. Strict validation stops the build before writing
the archive, so a resized image cannot silently ship with stale tile or sprite
atlas coordinates. Strict validation also rejects sprite frame crops that
extend past the atlas bounds or animation clips that name missing frames. The
warning names the frame and, for missing frames, the affected clip. For a
texture-backed tileset, a solid index outside its grid is rejected as well
because that tile could block movement without drawing any art. Autotile
variants that point outside the grid are also rejected, with the rule and
neighbour mask in the warning. A painted tile outside the grid is also
rejected when its texture-backed tileset is in the same cook. The message
gives the zero-based layer, cell and tile index. The Tilemap editor marks
those cells with a pink X, even beneath another layer. Hover for the layer
name and invalid tile, then repaint or erase on that layer. Deliberately empty cells or
variants are allowed.
After editing the source image outside Aether, choose **Reload tileset image**
to refresh both previews without saving the map or resetting Undo. If you
moved the image outside Aether, refresh the Content Browser first so it can
locate the asset by its metadata.
Left-drag to paint or right-drag to erase. Fast drags fill the cells between
pointer samples, and each drag is one undo step. **Fill** and **Pick** use
only the cell you click, even if you move the mouse while holding the button.
**Rectangle** starts on a
map cell and previews the fill until you release. It clips to the map edges;
press **Escape** during the drag to cancel. Right-drag still erases freehand
when Rectangle is selected, without changing the active tool. To rename, select the
layer, edit **Layer name**, and press **Enter**. **Move up** draws the selected
layer in front of more layers; **Move down** draws it behind more layers. The
brush stays on the same layer, and both renaming and moving are undoable.
**Duplicate** copies the selected layer and its collision setting just above
the original, selects the copy, and can be undone in one step. **Resize map**
changes the width and height while keeping the lower-left origin and all
overlapping tiles. Shrinking crops the top or right edge only after you
confirm; undo restores the cropped cells. Turn on **Solid** to outline every
cell that blocks movement, even when another layer's art covers it. Use the
checkbox next to a layer to decide whether its solid tiles block movement.
Hover a cell to see the layer you're editing and which layer is blocking it,
even when the two are different.

For a new tile sheet, right-click the image in the Content Browser and choose
**Create Tileset...**. Set the tile width and height in pixels, plus any
uniform outer margin and spacing. The grid must contain complete tiles. The
new tileset appears next to the image without replacing an existing asset.

To start a new map, right-click an existing **.atileset** in the Content Browser
and choose **Create Tilemap**. This creates and opens a blank 16 × 16 map with
one Ground layer, beside the tileset. Existing maps and metadata stay intact;
save the open map first if unsaved edits prevent the new map from opening.
Drag the saved **.atilemap** from the Content Browser into the scene hierarchy
to place a Tilemap Renderer at the origin, or into a scene viewport to place it
on the XY plane. Placement is one undo step. Save the scene to keep the asset
reference.

To edit the **2D Platformer** starter, open `Tiles/Level1.atilemap` in the
**Content Browser** rather than painting the Tilemap tool's practice map.
Practice changes are not saved. Opening a valid project tilemap replaces the
practice map, but unsaved changes to a project map are protected.
Use **Save tilemap and tileset** in that tool to write both assets. Cook and
Package wait for these edits to be saved so they don't ship the previous map.
Quitting also asks about unsaved project tilemaps. **Save and quit** writes
the tilemap and tileset before closing; a failed save leaves the editor open.
Save an edited tilemap before switching projects. The new project opens with
a fresh practice map rather than showing another project's assets.
Asset Validation reports when an atlas or tileset references an unknown
texture, or a map references an unknown tileset. It also names the referring
asset if the missing source still has an `.ameta` file. A strict package refuses
to ship a reachable asset whose referenced file is missing, whose 2D
header or reference is malformed, or whose reference points to the wrong
asset type (such as a Sprite Atlas in its own texture slot).

## 2D physics

Give an entity a `Rigidbody2D` (static, kinematic or dynamic) and a `Collider2D`
(a box or a circle; friction, restitution, a trigger flag, a layer and a mask).
Solid tiles provide static colliders, and moving bodies, including kinematic
bodies, detect tile contacts. Bodies don't rotate, which is what platformers
and top-down games want. Ask `Physics2D` for contact and trigger
events, `IsGrounded` and `WallSide`. Spatial queries include `Raycast` and
nearest-first `RaycastAll` (up to 64 hits), circle and axis-aligned box casts,
and point, box, oriented-box, circle and capsule overlaps. Casts report entity
or solid-tile hits; overlap queries return matching collider entities and can
filter by collision layer. Oriented boxes rotate counter-clockwise in radians;
capsules are defined by two segment endpoints and a radius.

## The platformer character

`PlatformerController2D` on a body turns the Move and Jump actions into running
and jumping with coyote time, jump buffering, variable jump height and a faster
fall; every number is a setting in the Inspector. `CameraFollow2D` makes a
camera follow it, optionally inside bounds.

## Jump Proof: verify a packaged route

Run a saved input sequence against a packaged player and check where its
single `Player`-tagged entity ends up. Jump Proof runs headlessly and reads
the usual replay `frames` and `events`, plus a rectangle in world coordinates:

```json
{
  "frames": 400,
  "events": [
    {"frame": 90, "key": "D", "value": 1},
    {"frame": 225, "key": "Space", "value": 1},
    {"frame": 285, "key": "Space", "value": 0},
    {"frame": 350, "key": "D", "value": 0}
  ],
  "target": {"min_x": 28.5, "max_x": 30, "min_y": 2, "max_y": 3}
}
```

Save it as `jump.json`, then run your packaged executable (use its `.exe`
on Windows):

```sh
./MyGame --jump-proof jump.json --user-dir ./JumpProofData
```

Use a fresh test profile, not your normal save folder. Exit `0` means the
player finished inside the target; exit `5` means the finished route missed.
Other nonzero exits indicate a setup or runtime error. The player prints one
`Jump Proof:` JSON verdict for a completed test, including the final position
and frame count. The same route can be run against two versions of a package.
This checks one input sequence, not whether every route is playable.

To generate the target around the observed finish instead of typing it,
record a fixed-step headless run into a new file:

```sh
./MyGame --headless --replay-input inputs.json --record-jump-route captured.json --user-dir ./CaptureData
./MyGame --jump-proof captured.json --user-dir ./ReplayData
```

The first run saves input changes and a target extending 0.25 world units
in each direction around the final position. It also saves the starting scene
and fixed tick rate. Jump Proof rejects a recording if the loaded scene or
package rate differs, before replaying any inputs. Existing routes that omit
both `scene` and `fixed_hz` still run; a route must supply both or neither.
A bounded `--frames` run with
`--press` also works. Recordings support up to 20,000 frames and never
overwrite an existing path. This does not record live keyboard play.

To see where two builds first disagree, capture both with `--jump-trace`
and compare the logs with the repository tool:

```sh
./Before/MyGame --jump-proof jump.json --user-dir ./BeforeData --jump-trace > before.txt
./After/MyGame --jump-proof jump.json --user-dir ./AfterData --jump-trace > after.txt
python3 tools/jump_proof_compare.py before.txt after.txt
```

The comparison reports the first post-tick frame whose X or Y differs by
more than 0.01 world units (use `--tolerance` to change it) and both positions.
It also reports each build's target verdict as `before_status` and
`after_status`. A pass-to-miss or miss-to-pass change returns exit `5` even
when all positions are within tolerance and `first_difference_frame` is null.
Exit `0` means both the verdict and path match within tolerance; it does not
mean the route passed. Exit `2` means invalid or incomplete input.
Trace input accepts UTF-8 with or without a byte-order mark and UTF-16
with a byte-order mark, including CRLF line endings. New captures reject
mismatched inputs, targets, scene names or simulation rates. Two older captures can still be compared,
but the result reports `"route_verified": false` because no route descriptor
was recorded. Use fresh profiles for both runs. An early divergence shows a
changed path, not by itself which edit caused it.

To see both paths on your map:

```sh
python3 tools/jump_proof_compare.py before.txt after.txt --overlay-data --output jump-overlay.json
```

The command writes UTF-8 JSON to a new file without shell redirection, even
when the comparison exits `5`. It never overwrites an existing file.
Open the map in **Tools > 2D > Tilemap**, expand **Jump Proof overlay**, enter
the JSON path, and select **Load overlay**. Blue shows the original path,
orange the changed path, with circles at the first position difference.
The overlay also shows the recorded target verdicts when present, even
when the positions are too close to place a difference marker. The overlay is
read-only, supports up to 20,000 frames, and assumes an unrotated tilemap at
world origin. Match **Pixels per unit** to the TilemapRenderer (16 for the starter).

For a controlled single-tile check, package the original project, change one
tile, then package it again with the same player and settings:

```sh
python3 tools/jump_proof_isolate_tile.py --pak-tool /path/to/aether_pak \
  --player MyGame --route jump.json Before After
```

The command verifies both distributions and refuses attribution if other
files, archive entries, or tilemap settings changed. It runs original,
changed, then original again in separate test profiles. A successful result
names the one changed cell (zero-based layer, X and Y) and the first
difference the repeated route exposed. It does not attribute multi-edit
regressions or establish that a level is now impossible to finish.

Append `--overlay-data --output jump-overlay.json` to write both paths and
the reported cell to a UTF-8 JSON file. This works without shell redirection,
including in Windows PowerShell. The command won't overwrite an existing file.
Load it in the Tilemap tool with the edited map open. The green outline appears
only when the asset path and edited cell value match. An ordinary replay
comparison never marks a tile.

## Lights

`Light2D` is a global, point or spot light with a colour, intensity, radius and
falloff; `ShadowCaster2D` boxes and solid tiles cast shadows. The module
computes the light at a point, a light map over a region, and each light's
visibility polygon, ready for a renderer to draw.

## The pixel-perfect camera

Set an orthographic camera 11.25 units high at 16 pixels a unit for a 320 x 180
view. `PixelPerfectCamera` shows a reference resolution at the largest
whole-number scale the window allows, with bars around it, and snaps positions
to the art's pixel grid.
