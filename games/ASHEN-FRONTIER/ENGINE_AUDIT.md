# Ashen Frontier: what the engine gives the design

The design document (DESIGN.md, section 16) says this must be audited before it is promised. This is the audit as of the first open-world build, written from the
engine's code and from running the game here, not from what the engine's own docs hope. **Have** = in the engine and used by this game or its proof game
(AETHER-01). **Have, unverified here** = in the engine, not yet exercised by this game. **Gap** = not there. A gap is not a reason to cut the design: where the game
needs it, the engine gets it (the rule for this project), and the row says what was done.

## What this build proves, and does not

Proved here (software Vulkan, `tools/smoke_test.py`): the project cooks; the player loads the open world (about 400 entities, a 115k-triangle terrain, a 118 x 118
collision grid); Kael walks the real terrain without falling through or floating, under the real controller; the layout data agrees with the terrain and the scene;
every region has 4 to 6 points of interest, each with content near it; each pass between regions is not a cliff.

Not proved: frame time and memory on a reference machine (no GPU here), anything on D3D12, the companion, combat, saving, or a person finishing the first 20 minutes.
